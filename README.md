# MMA3001-Project-repository

Automated inspection of packaged pork rasher trays: detection and localisation of packaging and meat-placement defects, with pass/fail classification, validation and speed benchmarking.

MMA3001 Numerical Methods and Machine Learning, individual project (2026).

## Engineering problem

On a meat-packing line, trays of pork rashers are checked for faults such as unsealed film, packaging errors, loose or twisted meat, and wrinkles. Manual inspection is slow and inconsistent. This project trains an object detector on camera frames of trays and turns its detections into a per-tray **pass/fail** decision, with the threshold chosen so that defective trays are rarely passed. It also measures whether inference is fast enough for a production line.

| | |
|---|---|
| **Input** | One RGB frame of a tray, 720 × 540 px (JPEG/PNG) |
| **Output** | Bounding boxes with class (`loose-meat`, `packaging-error`, `twisted-meat`, `unsealed`, `wrinkle`) and confidence in [0, 1]; a tray decision: **fail** if any box has confidence ≥ the operating threshold, otherwise **pass** |
| **Method** | YOLOv8 (Ultralytics), fine-tuned from COCO weights |
| **Validation** | Held-out test split; leakage audit between splits; manual label-quality review; threshold chosen on validation and reported on test with 95% Wilson intervals |

## Key results

All figures and tables are in [`results/`](results/), described in [`results/README.md`](results/README.md).

- **Data audit.** Four independent checks (file names, perceptual hash, neighbouring video frames, pixel correlation) found no tray in both training and evaluation splits. Manual review found 3 missed defects in the 12 unlabelled test images (25%, 95% CI 9–53%) and none in a sample of 24 unlabelled training images (0%, 95% CI 0–14%).
- **Selected model:** YOLOv8n at 640 px, chosen on validation mAP50-95 over YOLOv8s (640 px) and YOLOv8n (960 px).
- **Detection (test):** mAP50 0.50, mAP50-95 0.27. Unsealed 0.87 mAP50, packaging-error 0.42. Twisted and loose meat have only 3–4 test boxes and about 20 real training examples each, so their scores are not reliable; wrinkle has no test examples.
- **Tray pass/fail (test, corrected labels):** threshold 0.12 chosen on validation for ≤ 2% false passes; on test, 8.5% of defective trays passed and 22% of clean trays failed (only 9 clean test trays, so wide intervals).
- **Speed (Tesla T4):** 11.9 ms per image with FP16 (1.63× faster than FP32, same accuracy); about 92–99 ms on CPU. ONNX Runtime on CPU was slower and less accurate, so it was not adopted.

## Repository structure

```
src/rasher_inspection/   Python package
    dataset.py             download, parse and audit the dataset (leakage, label review)
    train.py               YOLO training, prediction, run status and resume
    evaluate.py            tray pass/fail decisions, error rates, threshold choice
    benchmark.py           inference timing
    stats.py               Wilson confidence intervals
    visualise.py           plotting helpers for manual inspection
notebooks/               Colab notebooks that run the package, in order
results/                 Committed outputs (tables, figures, review sheets) + index
tests/                   pytest tests (run on a small fake dataset)
docs/                    HTML API documentation generated by pdoc
reports/                 Test report (HTML, JUnit XML, coverage summary)
scripts/build_docs.sh    Regenerates docs/ and reports/
data/raw/                Downloaded dataset (git-ignored)
```

## Installation (local)

```bash
git clone https://github.com/rhal0027/MMA3001-Project-repository.git
cd MMA3001-Project-repository
pip install -r requirements.txt
pip install -e .
```

Results were produced with Python 3.13, PyTorch 2.11 and Ultralytics 8.3.40 on Colab. Colab's PyTorch version changes over time; `ultralytics` is pinned in `requirements.txt`.

## Documentation

HTML API documentation for every module, generated from the docstrings (Google style), is in [`docs/`](docs/): open `docs/index.html` in a browser.

## Tests

```bash
pytest
```

53 tests (unit tests and docstring examples) run in about a second on a small synthetic dataset, so no download, GPU or Ultralytics is needed. Line coverage is 93%; the uncovered lines are the Ultralytics training and prediction calls in `train.py`, which are exercised by running the notebooks. The latest report is in [`reports/`](reports/): `test_report.html` (open in a browser), `test_summary.txt` (with coverage table) and `junit.xml`.

To regenerate the documentation and the test report:

```bash
bash scripts/build_docs.sh
```

## Data

[Pork Rasher Error Packaging](https://universe.roboflow.com/hello-2aqe0/pork-rasher-error-packaging), Roboflow Universe, version 4, licensed CC BY 4.0: 3,549 images (1,955 originals before augmentation) with bounding-box labels and predefined train/validation/test splits. The data is not stored in this repository; `rasher_inspection.dataset.download_dataset` downloads it into `data/raw/`.
